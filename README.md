# Лабораторна робота №5



## Тема: Система контролю версій Git та співпраця через GitHub







Git - це розподілена система контролю версій, яка дозволяє відстежувати зміни в проєкті, працювати в команді, створювати гілки, об’єднувати їх та зберігати історію розробки.  



У цій лабораторній роботі демонструється створення локального та віддаленого репозиторію, налаштування SSH ключів, робота з гілками та структура реального проєкту.





## Мета заняття







- Навчитися створювати та налаштовувати Git-репозиторій.  



- Освоїти роботу з гілками (branching) та об’єднанням змін (merge / rebase).  



- Використовувати GitHub для зберігання віддаленого репозиторію.  



- Створювати коміти та робити історію змін зрозумілою.  



- Працювати з `.gitignore`, SSH-ключами та файлами конфігурації.  



- Практично застосувати Git на прикладі реального проєкту.





# Контрольні питання з Git







## 1. Основи



- Git — система контролю версій; GitHub — хостинг репозиторіїв.  



- Розподілена система — у кожного повна копія репозиторію.  



- `git init` створює новий репозиторій; `git clone` копіює існуючий.







## 2. Staging та коміти



- Staging — зона, де визначають, що піде в коміт.  



- `git add .` - зміни в поточній папці; `git add -A` - всі зміни.  



- Коміт-меседж має бути коротким і зрозумілим.  



- Виправити останній коміт: `git commit --amend`.







## 3. Гілки і злиття



- Гілка — легкий покажчик на коміт.  



- `merge` об’єднує історію; `rebase` переписує її.  



- Fast-forward - пересування покажчика без нового коміту.  



- Конфлікти - коли змінено одні й ті самі рядки.  



- Публічні коміти не rebase-ять, щоб не ламати історію.







## 4. Віддалені репозиторії



- `origin` — назва віддаленого репо за замовчуванням.  



- `git fetch` отримує зміни; `git pull` також застосовує їх.  



- `git push --force` перезаписує історію — небезпечно.  



- Видалити віддалену гілку: `git push origin --delete <branch>`.







## 5. Скасування змін



- `reset --soft` — тільки HEAD; `--mixed` — очищає staging; `--hard` — стирає зміни.  



- `reset` змінює історію; `revert` створює коміт-скасування.  



- Скасувати `git add`: `git reset`.  



- Повернути видалений файл: `git checkout HEAD -- <file>`.







## 6. Безпека



- Не комітити паролі, ключі, токени, великі бінарні файли.  



- Випадковий пароль у коміті - негайно відкликати й прибрати з історії.  



- SSH зручніший для постійної роботи.  



- Personal Access Token — ключ доступу замість пароля.







## 7. GitHub



- Pull Request — пропозиція злиття змін.  



- Issues - задачі; PR - зміни коду.  



- Fork — власна копія чужого репозиторію.  



- GitHub Actions — автоматизація (CI/CD).







## 8. Best Practices



- Комітити часто й маленькими порціями.  



- Feature-гілки мають жити недовго.  



- Використовувати workflow з гілками та PR.  



- `node\\\_modules` не комітити.
